### 3.2 KaTeX / MDX v3 Formatting Rules

Docusaurus 3 relies on the MDX v3 engine. Unlike standard CommonMark, MDX v3 parses `{` and `}` as JavaScript expressions and treats XML/HTML-like syntax strictly. All authors must adhere to the following rules:

1. **Heading Safety (H1–H6)**:
   - **Never** include unescaped `{`, `}`, `<`, or `>` in Markdown headers.
   - ❌ Broken: `## Recursive Newton-Euler: O({n}) Complexity`
   - ✅ Correct: `## Recursive Newton-Euler: O(n) Complexity`
   - ❌ Broken: `### When Latency < 1ms`
   - ✅ Correct: `### When Latency Is Under 1 ms`
2. **Inline Math Formatting**:
   - Delimit inline math with single dollar signs: `$math$`.
   - **No inner whitespace**: The opening `$` must be immediately followed by a non-whitespace character, and the closing `$` must be immediately preceded by a non-whitespace character.
   - ❌ Broken: `$ \tau = M(q)\ddot{q} $`
   - ✅ Correct: `$\tau = M(q)\ddot{q}$`
3. **Block / Display Math Formatting**:
   - Block math must use double dollar signs `$$` situated on their own independent lines.
   - Example:
     ```latex
     $$
     M(q)\ddot{q} + C(q,\dot{q})\dot{q} + g(q) = \tau + \sum_{k} J_{c,k}^T f_{c,k}
     $$
     ```
4. **Markdown Table Math Protection**:
   - Markdown tables interpret the pipe character `|` as a column divider.
   - If a LaTeX math formula in a table contains `|` (e.g. absolute value, norm, conditional probability), it will break the table layout or cause MDX parser crashes.
   - Authors **must** use LaTeX escape commands:
     - Absolute value: Use `$\vert x \vert$` instead of `$|x|$`.
     - Vector/Matrix norm: Use `$\Vert x \Vert$` or `$\|x\|$` instead of `$||x||$`.
     - Conditional probability: Use `$P(A \mid B)$` instead of `$P(A|B)$`.
     - Set builder notation: Use `$\{ x \in \mathcal{X} \mid f(x) > 0 \}$`.
5. **Prose Escaping for Curly Braces**:
   - Any literal `{` or `}` appearing in body text (outside of a code block or KaTeX formula) must be enclosed in inline backticks or escaped with a backslash:
     - ❌ Broken: Check the value of {node_name} before spawning.
     - ✅ Correct: Check the value of `{node_name}` before spawning.
     - ✅ Correct: Check the value of \{node_name\} before spawning.
6. **JSX Self-Closing Tags**:
   - In MDX v3, any void HTML elements must be self-closing: `<br />`, `<hr />`, `<img ... />`.

### 3.4 Interactive Component Embedding Guidelines

Each chapter must embed the two interactive platform components: `<ChapterProgress />` and `<QuizEngine />`.

#### A. Component Imports
At the top of each `.mdx` chapter (immediately after the frontmatter closing `---`), include the component imports:
```mdx
import ChapterProgress from '@site/src/components/ChapterProgress';
import QuizEngine from '@site/src/components/QuizEngine';
```

#### B. `<ChapterProgress />` Specification
- **Placement**: Place near the bottom of each chapter, directly preceding the Quiz Engine or following the chapter summary.
- **Attributes**:
  - `chapterId`: The slug corresponding to the filename without extension (e.g. `"1-11-ros2-control"`, `"3-6-cuvslam-and-state-estimation"`).
  - `moduleId`: The normalized module key (`"module1"`, `"module2"`, `"module3"`, `"module4"`).
  - `totalChapters`: The total number of chapters in the module (`14` for Module 1, `10` for Modules 2, 3, and 4).
- **Example**:
  ```mdx
  <ChapterProgress chapterId="1-11-ros2-control" moduleId="module1" totalChapters={14} />
  ```

#### C. `<QuizEngine />` Specification
- **Placement**: Place at the conclusion of the chapter as the "Chapter Mastery Check".
- **Attributes**:
  - `quizId`: Unique string identifier formatted as `"quiz-<chapterId>"` (e.g. `"quiz-1-11"`).
  - `title`: String title (e.g. `"Module 1.11 Mastery Check: ros2_control"`).
  - `moduleId`: Normalized module key (e.g. `"module1"`).
  - `passThreshold`: Integer percentage threshold, typically `70`.
  - `questions`: Array of 2 to 4 `QuizQuestion` objects:
    - `id`: Unique string ID (e.g. `"q1"`, `"q2"`).
    - `question`: Concise question text.
    - `options`: Array of 3 to 4 string choices.
    - `correctIndex`: 0-based integer pointing to the correct choice.
    - `explanation`: Thorough pedagogical explanation of why the correct option is right and the others are incorrect.
- **Example**:
  ```mdx
  <QuizEngine
    quizId="quiz-1-11"
    title="Module 1.11 Mastery Check: ros2_control Hardware Abstraction"
    moduleId="module1"
    passThreshold={70}
    questions={[
      {
        id: "q1",
        question: "Which ros2_control interface must be implemented to integrate an EtherCAT motor drive that accepts torque commands and returns position/velocity feedback?",
        options: [
          "SensorInterface",
          "ActuatorInterface",
          "SystemInterface",
          "BroadcasterInterface"
        ],
        correctIndex: 1,
        explanation: "ActuatorInterface is designed specifically for 1-DoF or modular actuators that accept commands (e.g. effort/torque) and provide sensor feedback (e.g. encoder readings) across a fieldbus."
      },
      {
        id: "q2",
        question: "In real-time ros2_control loops, why is dynamic memory allocation (e.g. new, malloc) strictly prohibited inside the read() and write() methods?",
        options: [
          "It causes compile-time errors in C++20",
          "It triggers OS page faults and unbounded heap latency, violating the 1 ms control loop budget",
          "EtherCAT communication packets only support static memory addresses",
          "ROS 2 executors cannot serialize dynamically allocated variables"
        ],
        correctIndex: 1,
        explanation: "Dynamic memory allocation can invoke the kernel virtual memory manager to allocate physical pages, resulting in non-deterministic page faults and latency spikes that breach hard real-time deadlines."
      }
    ]}
  />
  ```

## 5. Edge Cases

| # | Feature | Input | Observed Behavior |
|---|---------|-------|-------------------|
| 1 | MDX v3 Parser | Unescaped curly brace in heading: `## Step {1}` | Build failure: Acorn parser error expecting identifier. Must be plain text `## Step 1`. |
| 2 | MDX v3 Parser | Set notation in prose: `Let S = {s1, s2}` | Build failure if not inside backticks or escaped. Must be `` `{s1, s2}` `` or `$\{s1, s2\}`. |
| 3 | KaTeX Math | Unclosed math delimiter: `$\tau = M(q)` without trailing `$` | Remark-math fails to parse delimiter; text renders raw or breaks Docusaurus build. |
| 4 | KaTeX in Tables | Raw pipe in math: `| Absolute Value | $|x|$ |` | Markdown table parser interprets `|` as column delimiter, breaking table formatting and crashing MDX parser. Must use `$\vert x \vert$`. |
| 5 | Docusaurus Sidebar | Missing `sidebar_position` in frontmatter | Chapter defaults to alphabetical sorting by filename rather than pedagogical sequence. |
| 6 | Docusaurus Sidebar | Duplicate `sidebar_position` (e.g. two chapters with position `6`) | Order becomes non-deterministic between the two items. Positions must be strictly sequential (1..14, 1..10). |
| 7 | ChapterProgress | User opens page in Incognito mode with `localStorage` disabled | Component catches SecurityError in try/catch; defaults to in-memory state without crashing. |
| 8 | QuizEngine | User submits quiz without answering all questions | Submit button remains disabled and validation notice displays unanswered count. |
| 9 | QuizEngine | Pass threshold passed as decimal `0.70` instead of `70` | Component normalizes `passThreshold <= 1 ? Math.round(passThreshold * 100) : passThreshold` automatically. |
| 10 | Code Blocks | Code fence with no language tag: ```` ``` ```` | Prism highlighter cannot syntax color; generates build warning. Must always use `python`, `cpp`, etc. |

## 6. Caveats

1. **Frontmatter Descriptions in Existing Chapters**: Existing files in Modules 1, 2, and 3 currently omit `description:` frontmatter tags. The enhancement tasks must inject the exact descriptions specified in Section 3.1 into these existing files to optimize search indexing and social cards.
2. **Global Component Swizzling**: Currently, `src/theme/MDXComponents.tsx` is not swizzled. If authors embed `<ChapterProgress />` or `<QuizEngine />` without explicit top-level imports in each `.mdx` file, `npm run build` will throw a reference error (`ChapterProgress is not defined`). Authors must either import them at the top of each file or the orchestrator should provide a swizzled `src/theme/MDXComponents.tsx`.
3. **External Dependencies in Code Examples**: Code examples in chapters reference external libraries (`rclpy`, `pinocchio`, `casadi`, `isaacsim`, `torch`). Code blocks should be runnable self-contained modules, but documentation build verification does not execute code blocks in Python runtime.

### 3.3 Critical MDX v3 Compilation Safety Rules

Docusaurus 3 uses the MDX v3 compiler (`@mdx-js/react@3`), which parses Markdown content through the Acorn JavaScript parser. Any syntax resembling JavaScript or unescaped JSX causes compilation errors that abort `npm run build`.

#### Rule 1: Frontmatter Standardization
Every chapter MUST begin with a frontmatter block containing exactly three attributes:
```yaml
---
sidebar_position: <integer>
title: "<Full Human-Readable Title>"
description: "<1-2 sentence concise summary without quotes or special symbols>"
---
```
- `sidebar_position`: Must be an integer strictly between `1` and `totalChapters` (unique per module).
- `title`: Enclosed in double quotes. Do not include raw LaTeX formulas or curly braces in titles.
- `description`: Enclosed in double quotes. Required for SEO meta tags and vector retrieval chunk summaries.

#### Rule 2: Mandatory Component Imports
Because `src/theme/MDXComponents.tsx` is not swizzled, every `.mdx` file MUST explicitly import interactive components immediately after the frontmatter closing delimiter:
```mdx
import ChapterProgress from '@site/src/components/ChapterProgress';
import QuizEngine from '@site/src/components/QuizEngine';
```
*Consequence if omitted*: Build fails with `ReferenceError: ChapterProgress is not defined` or `QuizEngine is not defined`.

#### Rule 3: KaTeX Math Delimiter Rules
- **Inline Math**: Single dollar signs `$math$`.
  - **Zero inner whitespace**: Opening `$` must directly touch the first character, and closing `$` must directly touch the last character.
  - ❌ Broken: `$ \tau = M(q)\ddot{q} $`
  - ✅ Correct: `$\tau = M(q)\ddot{q}$`
- **Display / Block Math**: Double dollar signs `$$`.
  - Must occupy isolated lines separated from prose by blank lines:
    ```latex
    $$
    \tau = M(q)\ddot{q} + C(q,\dot{q})\dot{q} + g(q)
    $$
    ```
- **No Unescaped Currency Dollar Signs**: Any literal currency dollar sign in prose must be written as `\$100` or enclosed in inline code `` `$100` ``.

#### Rule 4: Prohibition of Raw Curly Braces in Prose and Headings
In MDX v3, curly braces `{` and `}` are parsed as JavaScript expression interpolations.
- **In Headings (`#`, `##`, `###`)**:
  - ❌ Broken: `## Time Complexity of O({n})`
  - ✅ Correct: `## Time Complexity of O(n)`
  - ❌ Broken: `### When Latency < 1ms`
  - ✅ Correct: `### When Latency Is Under 1 ms`
- **In Prose Text**:
  - Any literal `{` or `}` must either be wrapped in inline backticks or escaped with a backslash:
    - ❌ Broken: Update the parameter {learning_rate} before training.
    - ✅ Correct: Update the parameter `{learning_rate}` before training.
    - ✅ Correct: Update the parameter \{learning_rate\} before training.
  - Set notation in prose:
    - ❌ Broken: Consider state set S = {s1, s2, s3}.
    - ✅ Correct: Consider state set `S = {s1, s2, s3}`.
    - ✅ Correct (in math): Consider state set $S = \{s_1, s_2, s_3\}$.

#### Rule 5: Markdown Table Pipe Protection
Markdown table parsers interpret the pipe character `|` as a cell column delimiter. If a LaTeX formula inside a table contains `|`, it breaks table column boundaries and triggers an unrecoverable MDX parse failure.
- **Absolute Value**: Always use `\vert` instead of raw `|`.
  - ❌ Broken in table: `| Absolute Error | $|e_k|$ |`
  - ✅ Correct in table: `| Absolute Error | $\vert e_k \vert$ |`
- **Vector / Matrix Norm**: Always use `\Vert` instead of `||`.
  - ❌ Broken in table: `| State Norm | $||x||_2$ |`
  - ✅ Correct in table: `| State Norm | $\Vert x \Vert_2$ |`
- **Conditional Probability / Notation**: Always use `\mid` instead of `|`.
  - ❌ Broken in table: `| Policy | $\pi(a|s)$ |`
  - ✅ Correct in table: `| Policy | $\pi(a \mid s)$ |`
- **Set Builder Notation**: Always use `\mid` and `\{ \}`:
  - ✅ Correct in table: `| Feasible Set | $\{ u \in \mathcal{U} \mid Au \le b \}$ |`

#### Rule 6: Code Block Standards
- All code fences must include an explicit language specifier (e.g. ```` ```python ````, ```` ```cpp ````, ```` ```bash ````, ```` ```json ````, ```` ```yaml ````, ```` ```mermaid ````). Bare ```` ``` ```` fences are strictly prohibited.
- Python code examples must target Python 3.10+ / 3.13 with modern typing (`list[float]`, `dict[str, Any]`).
- Code blocks must include all necessary import statements so they are fully self-contained.

## 5. Edge Cases

| # | Feature | Input | Observed Behavior |
|---|---------|-------|-------------------|
| 1 | MDX v3 Parser | Heading containing curly braces: `## Algorithmic Complexity {O(n)}` | `npm run build` crashes: Acorn parser syntax error expecting JavaScript identifier. Must be `## Algorithmic Complexity O(n)`. |
| 2 | MDX v3 Parser | Prose containing unescaped braces: `Define the state tuple {q, v, tau}` | `npm run build` crashes: Acorn parser treats `{q, v, tau}` as object literal. Must be enclosed in inline code backticks `` `{q, v, tau}` `` or escaped `\{q, v, tau\}`. |
| 3 | KaTeX Delimiter | Math with inner whitespace: `$ \tau = M(q)\ddot{q} $` | `remark-math` fails to recognize opening/closing delimiters; renders raw text or breaks math parsing. Must be tight: `$\tau = M(q)\ddot{q}$`. |
| 4 | Markdown Table Math | LaTeX absolute value with raw pipe in table: `\| Absolute Error \| $\vert e_k \vert$ \|` vs `\| $|e_k|$ \|` | Raw `$|e_k|$` splits table column in Markdown parser, corrupting table layout and crashing MDX compiler. Must use `\vert`, `\Vert`, `\mid`. |
| 5 | Docusaurus Sidebar | Missing `sidebar_position` frontmatter tag in chapter | Autogenerated category falls back to alphabetical filename order, breaking curriculum pedagogical sequence. |
| 6 | Docusaurus Sidebar | Duplicate `sidebar_position` values (e.g. two files with position `4`) | Docusaurus ordering becomes non-deterministic between duplicate files. Positions must be strictly sequential 1..N. |
| 7 | Component Imports | Missing component import at top of `.mdx` file | `npm run build` throws `ReferenceError: ChapterProgress is not defined` or `QuizEngine is not defined` during server-side static rendering. |

| 9 | QuizEngine Questions | Question object has empty `options: []` or missing `correctIndex` | Component default values prevent runtime null pointer exceptions; however, quiz fails pedagogical utility. All questions must provide 3-4 options and valid `correctIndex`. |
| 10 | Code Highlighting | Code fence with missing language tag: ```` ``` ```` | Docusaurus Prism highlighter falls back to plaintext; outputs build warning or fails linting. Must always supply `python`, `cpp`, `bash`, etc. |

## 6. Caveats

1. **Directories Uncreated Prior to Authoring**:
   - The four directories (`module6-bipedal-locomotion`, `module7-dexterous-manipulation`, `module8-robot-learning`, `module9-sim-to-real`) do not exist yet. Workers must create the directory AND its `_category_.json` file before or alongside authoring chapter `.mdx` files.

   - Because `src/theme/MDXComponents.tsx` is not swizzled, every single authored chapter MUST include the explicit `import ChapterProgress` and `import QuizEngine` lines. If omitted in even one file, `npm run build` will fail globally.
3. **Pipes Inside Markdown Tables**:
   - In advanced robotics documentation, absolute values ($|x|$), norms ($||x||$), and conditional distributions ($P(s'|s,a)$) are frequent. Authors must be vigilantly reminded to replace all math pipes inside tables with `\vert`, `\Vert`, and `\mid`.
4. **Offline Build Verification**:
   - Static asset building via `npm run build` tests MDX compilation, KaTeX parsing, React SSR rendering, and link integrity, but does not execute Python code blocks. Code blocks must be verified for syntax and typing independently.

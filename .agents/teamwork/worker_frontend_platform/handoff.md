## 2. Logic Chain

1. **KaTeX Integration**:
   - Docusaurus 3 uses MDX 3 (ESM-based). Older `remark-math` v3/v5 or `rehype-katex` v4 cause ESM syntax errors.
   - Installing `remark-math@^6.0.0` and `rehype-katex@^7.0.1` and attaching them to `@docusaurus/plugin-content-docs` enables native LaTeX math rendering (`$...$` and `$$...$$`) across all MDX chapters.
   - Adding the official KaTeX CDN stylesheet guarantees typography and formula glyphs render accurately.

2. **Component Architecture & SSR Resilience**:
   - In Docusaurus SSG builds, components are rendered in Node.js where `window` and `localStorage` are undefined.
   - Using `@docusaurus/useIsBrowser` and checking `typeof window !== 'undefined'` ensures `ChapterProgress` and `QuizEngine` render SSR-safe skeletons on the server and activate stateful `localStorage` behavior on client mount without hydration mismatch.
   - Network requests to `/analytics` are wrapped in `try/catch` and `.catch(() => {})`, ensuring client components never crash when offline or if the backend telemetry service is uninitialized.

3. **Navigation & Broken Links Resolution**:
   - Docusaurus enforces `onBrokenLinks: 'throw'`. Modules 6–12 are authored in Phase 2 (Milestones M3 and M4) and do not yet have chapter files on disk.
   - If navbar, footer, or sidebar hardcoded paths to non-existent markdown files, `docusaurus build` would fail with broken link errors.
   - By structuring `ai-book-docs/sidebar.ts` and `docusaurus.config.ts` to inspect file presence on disk, all 12 modules are registered immediately; existing chapters link directly to content, and planned modules gracefully resolve to curriculum roadmap links until chapter authoring completes.
   - Once M3 and M4 author the chapters, the sidebar and navigation automatically pick up the new files without requiring any code edits.

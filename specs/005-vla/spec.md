## User Scenarios & Testing

### User Story 1 - Voice Command to Text Conversion (Priority: P1)

Students will be able to convert spoken voice commands into text using Whisper, forming the initial step of the Vision-Language-Action pipeline.

**Why this priority**: This is the fundamental input mechanism for VLA systems, essential for all subsequent language processing and action planning.

**Independent Test**: Can be fully tested by running a voice command through Whisper and verifying that the correct textual transcription is produced.

**Acceptance Scenarios**:

1. **Given** a student provides an audio input with a simple command (e.g., "pick up the red block"), **When** Whisper processes the audio, **Then** an accurate text transcription of the command is generated.
2. **Given** various voice inputs with different accents or background noise, **When** Whisper processes the audio, **Then** the system demonstrates reasonable robustness in transcribing the commands into text.

---

### User Story 2 - LLM-based Cognitive Planning (Priority: P1)

Students will learn to use Large Language Models (LLMs) for high-level task planning, translating natural language commands into a sequence of executable robot actions.

**Why this priority**: This is the core cognitive component of a VLA system, enabling intelligent decision-making and breaking down complex commands into manageable steps.

**Independent Test**: Can be fully tested by providing a natural language command to an LLM and verifying that it generates a logical and correct sequence of robot actions or sub-goals.

**Acceptance Scenarios**:

1. **Given** a natural language command (e.g., "Clean the room") is provided to an LLM-based task planner, **When** the LLM processes the command, **Then** it generates a structured action graph or sequence of high-level robot tasks (e.g., "go to table", "pick up cup", "put cup in sink").
2. **Given** a specific command (e.g., "Pick up the cup"), **When** the LLM is used for planning, **Then** it translates this into a series of actionable ROS 2 commands (e.g., "move arm to cup location", "close gripper").

---

### User Story 3 - Natural Language to ROS 2 Action Conversion (Priority: P2)

Students will be able to convert the high-level plans generated by LLMs into concrete ROS 2 actions that a robot can execute.

**Why this priority**: This bridges the gap between abstract AI planning and physical robot control, allowing for real-world execution of cognitive commands.

**Independent Test**: Can be fully tested by taking an LLM-generated action sequence and successfully converting it into executable ROS 2 action server calls or messages, verifying proper command formatting and target execution.

**Acceptance Scenarios**:

1. **Given** an LLM output detailing an action like "grasp object", **When** the conversion module processes this, **Then** it generates the appropriate ROS 2 action goal message for a robot gripper action server.
2. **Given** a sequence of ROS 2 actions generated from an LLM plan, **When** these actions are sent to a simulated humanoid robot, **Then** the robot performs the intended physical movements (e.g., reaching, grasping, moving).

---

### Edge Cases

- What happens if Whisper misinterprets a voice command, leading to an incorrect text transcription? (Expected: Discussion on error propagation, potential for user clarification, or recovery mechanisms).
- How does the LLM handle ambiguous or impossible commands (e.g., "fly to the moon")? (Expected: The LLM should identify the command as infeasible or request clarification, possibly through safety layers).
- What if the conversion from natural language to ROS 2 actions is incomplete or contains errors? (Expected: The robot either fails to execute, performs an unintended action, or a safety layer intervenes).
- How are security and safety concerns addressed when an LLM is directly generating robot commands? (Expected: Discussion on safety protocols, human oversight, and constraints on LLM output).

### Key Entities

- **Vision-Language-Action (VLA) System**: A cognitive architecture that integrates visual perception, natural language understanding, and robot action execution.
- **OpenAI Whisper**: A general-purpose speech recognition model.
- **Large Language Model (LLM)**: An AI model capable of understanding and generating human-like text, used here for high-level planning.
- **ROS 2 Action Server**: A ROS 2 component that provides a goal-based interface for long-running robot tasks.
- **Intent Extraction**: The process of identifying the user's underlying purpose or goal from their natural language input.
- **Task Breakdown**: The process of decomposing a complex high-level task into a sequence of smaller, manageable sub-tasks or actions.
- **Action Graph**: A structured representation of a sequence of actions and their dependencies, often used in robot planning.
